The Blueprint

Project 01 - Voucher & Offers System

THE BRIEF

Design a voucher card component and its detail screen for HOP's mobile booking flow, based on provided content and reference designs. The card needed to work within the existing checkout experience where users select a ride, choose payment, and optionally apply a voucher before booking.

IDEATION & WIREFRAMING

Before going high-fidelity, I sketched two key screens — the voucher card layout and the detail view — to validate the information hierarchy.

This ensured the most critical information was immediately visible without opening the detail screen.

INITIAL DESIGN

My first version focused on the visual structure of the card and detail screen based on the content brief. The design featured a clean ticket-shaped card with offer type tags, discount badge, promotional illustration, and a detail screen with non-collapsible information sections.

THE FEEDBACK

After submission, the Mobile Dev Lead raised four specific concerns based on the actual booking flow context I hadn't been given access to initially:

"Given the above context, a voucher needs to be selectable, however, the new design of the voucher cards do not have an active state that signifies that it is the one currently chosen."

The four concerns were:

  • Missing selected state on the voucher card
  • No promo code / gift code input field
  • CTA label said "Book a Ride Now" — incorrect given the user is already in a pending booking.
  • Inconsistent collapsible sections across the detail screen

MY RESPONSE

I acknowledged the gaps, requested access to the full booking flow Figma file, and revised all four concerns within 24 hours:

  • Added a selected state with teal border and checkmark to the voucher card
  • Added a promo/gift code input field with Apply button and error state
  • Updated the CTA to "Apply Voucher"
  • Made all information sections non-collapsible
    for consistency

APPROVAL

"Great job on the new designs, it addresses all of my concerns and looks amazing as well. The Special Offers section is now 100% ready for dev."
— Mobile Dev Lead, HOP Services

COMPONENTS

I built a focused component set for the voucher system, extending HOP's existing design system.

Project 02 - Apply as Driver Page

THE BRIEF

Design the Apply as Driver page for the HOP website. The page needed three main sections: a registration form for aspiring drivers, a Driver Handbook Guide with collapsible sections and a download option, and a QR code linking to the HOP mobile app for app-based applications.

HIGH-FIDELITY DESIGN

I designed both desktop and mobile versions within HOP's existing website design system, organizing the form into four logical field groups to reduce cognitive load for applicants.

FORM STRUCTURE

The 11-field application form was grouped into four sections to guide applicants through the process without overwhelming them:

  • Personal Information — Full Name, Contact Number, Email Address
  • Driver Details — Age, Years of Driving Experience, License Number
  • Vehicle Information — Vehicle Type (dropdown), Vehicle Model/Year
  • Document Uploads — Driver's License, OR/CR, Valid ID

DRIVER HANDBOOK

The handbook was designed as a collapsible card system covering Driver Qualifications, Vehicle Requirements, Required Documents, Onboarding Process, and Responsibilities — with a Download Handbook CTA for offline reference.

APP INTEGRATION

A QR code section in the hero area allows prospective drivers to apply directly through the mobile app — giving HOP two application channels from a single page.

APPROVAL

The design was transferred directly to the main HOP Figma file for development with no revisions required.

"Since no need for revisions, I'll just base it on the schema provided."
— Lead Developer, HOP Services

Reflection &
Final Thoughts

“Both designs were approved directly for development at HOP Services — not
into a portfolio archive,
but into real code for a product launching in December 2026.”

What I Learned

The voucher project taught me my most important professional lesson — always understand the full user flow before designing a component. When the Mobile Dev Lead raised concerns, I treated his feedback as information, requested the missing context, and revised all four issues within 24 hours. The driver page taught me that clean information architecture makes complexity feel simple. Grouping 11 fields into four sections isn't just visual organization — it's UX thinking that reduces anxiety for someone making an important life decision.

The Validation

The Mobile Dev Lead reviewed my revised voucher card and confirmed it was "100% ready for dev" — the phrase every product designer wants to hear. The driver application page was approved with zero revisions, moving directly into the main Figma file for development. Neither design needed a second round. Both shipped.

What I’m Most Proud Of

Both designs went directly into development. Not into a feedback loop that faded, not into a portfolio archive — into actual code for a real product launching in December 2026. That's what separates this internship from a personal project. And knowing that real drivers will eventually use the page I designed to start their HOP journey is exactly why I love this work.
